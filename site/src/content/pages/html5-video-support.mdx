## Why isn't HTML5 video enough?

A bare `<video>` tag is fine for a short clip with the browser's default controls. A real player needs more:

- Adaptive streaming. Safari and a few mobile browsers play HLS natively, and no browser plays DASH natively. Everywhere else, you need a JavaScript engine built on Media Source Extensions.
- Controls that look the same everywhere. Chrome, Safari, and Firefox each draw their own. You can turn them off, but you can't restyle them.
- Menus for captions, quality, and playback speed, plus chapter markers. The browser gives you none of these.
- Accessibility. Once you replace the native controls, keyboard shortcuts, focus handling, screen reader labels, and reduced motion are your job.
- Thumbnail previews, live stream UI, AirPlay, Chromecast, error recovery, and analytics, plus YouTube and Vimeo embeds that use the same controls as your own video.

Video.js covers all of this, and each piece is a separate component, so you only ship what you use. <DocsLink slug="guides/why-videojs">Why Video.js?</DocsLink> goes into more detail.

## Get started with Video.js

A basic player looks like this:

```html title="index.html"
<script type="module" src="{{VJS10_CDN_BASE}}/video.js"></script>

<video-player>
  <video-skin>
    <video src="/video.mp4" playsinline></video>
  </video-skin>
</video-player>
```

```tsx title="MyPlayer.tsx"
import '@videojs/react/video/skin.css';
import { Video, VideoPlayer, VideoSkin } from '@videojs/react/video';

export function MyPlayer({ src }: { src: string }) {
  return (
    <VideoPlayer>
      <VideoSkin>
        <Video src={src} playsInline />
      </VideoSkin>
    </VideoPlayer>
  );
}
```

The <DocsLink slug="guides/installation">installation guide</DocsLink> generates a snippet for your framework, video source, and features.

Still on Video.js 8? Its docs live at [legacy.videojs.org](https://legacy.videojs.org), and <DocsLink slug="guides/migrate-from-video-js-8">Migrate from Video.js 8</DocsLink> covers the upgrade.

## Where to host the video

The player is half the job. Adaptive streaming also needs each upload transcoded into several resolutions, packaged as HLS, and served from a CDN. You can build that yourself with ffmpeg and a storage bucket, or let a service do it.

We build Video.js at Mux, so we're biased, but this is what [Mux Video](https://www.mux.com/video) is for. Upload a file, get back a playback ID, and stream it with `<mux-video>` in place of `<video>`:

```html title="index.html"
<script type="module" src="{{VJS10_CDN_BASE}}/video.js"></script>
<script type="module" src="{{VJS10_CDN_BASE}}/media/mux-video.js"></script>

<video-player>
  <video-skin>
    <mux-video src="https://stream.mux.com/YOUR_PLAYBACK_ID.m3u8" playsinline></mux-video>
  </video-skin>
</video-player>
```

```tsx title="MyPlayer.tsx"
import '@videojs/react/video/skin.css';
import { MuxVideo } from '@videojs/react/media/mux-video';
import { VideoPlayer, VideoSkin } from '@videojs/react/video';

export function MyPlayer({ playbackId }: { playbackId: string }) {
  return (
    <VideoPlayer>
      <VideoSkin>
        <MuxVideo source={{ playbackId }} playsInline />
      </VideoSkin>
    </VideoPlayer>
  );
}
```

The quickest way to try it is the <DocsLink slug="guides/installation">installation guide</DocsLink>: drop in a video, sign in to Mux, and it comes back as a free HLS stream already wired into your snippet. Once real viewers are watching, <DocsLink slug="guides/mux-data">Mux Data</DocsLink> shows you startup time, rebuffering, and errors for every view.
