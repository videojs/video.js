Video.js uses opaque semantic keys so English copy can change without breaking translation packs. English defaults are defined in `packages/core/src/core/i18n/locales/en.ts`. Both HTML and React controls use the same keys.

<FrameworkCase frameworks={["react"]}>
Locale packs and provider overrides use nested objects, so `buttons.play` is authored as `{ buttons: { play: '…' } }`. Translators use the dotted form.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
Locale packs and provider overrides use nested objects, so `buttons.play` is authored as `{ buttons: { play: '…' } }`. Translators and the `<media-text token>` attribute use the dotted form.
</FrameworkCase>

## Text descriptors

Each key also ships as a text descriptor: an object with the `key` and its English default `text`. Descriptors are grouped by the key's first segment and named after the rest, so `buttons.play` is `playText` in the `buttons` module and `container.label` is `labelText` in `container`. Pass one to a translator, or to <DocsLink slug="reference/api/translate-text">`translateText`</DocsLink>, to get the active locale's copy with English as the fallback.

<FrameworkCase frameworks={["react"]}>
```tsx
import { useTranslator } from '@videojs/react/i18n';
import { playText } from '@videojs/react/i18n/text/buttons';

function PlayLabel() {
  const t = useTranslator();

  return <span>{t(playText)}</span>;
}
```
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
```ts
import { createTranslator, getI18nTranslations } from '@videojs/html/i18n';
import { playText } from '@videojs/html/i18n/text/buttons';

const t = createTranslator(getI18nTranslations('fr'), 'fr');

t(playText); // 'Lecture' once French is registered, else 'Play'
```
</FrameworkCase>
