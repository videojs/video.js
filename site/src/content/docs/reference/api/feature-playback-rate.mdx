Controls speed of playback. `playbackRateAvailability` is `unsupported` when the media has no playback rate, such as an embed whose provider takes no speed command.

### Playback rates

The player offers `0.5` through `2` in steps of `0.25` unless you set your own list. The <DocsLink slug="reference/components/playback-rate-button">playback rate button</DocsLink>, the <DocsLink slug="reference/components/playback-rate-radio-group">playback rate radio group</DocsLink>, and the `speedUp` and `speedDown` <DocsLink slug="guides/keyboard-shortcuts">hotkeys</DocsLink> use this list unless you give one of them its own.

<FrameworkCase frameworks={["react"]}>
Pass `defaultPlaybackRates` to <DocsLink slug="reference/components/player">`Player`</DocsLink>:

```tsx
<Player defaultPlaybackRates={[0.5, 1, 1.25, 1.5, 2]}>
  <Container>
    <Video src="/video.mp4" />
  </Container>
</Player>
```

Removing the prop, or passing `null`, restores the defaults.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
Set the `default-playback-rates` attribute on <DocsLink slug="reference/components/player">`<video-player>`</DocsLink> to a space-separated list:

```html
<video-player default-playback-rates="0.5 1 1.25 1.5 2">
  <media-container>
    <video src="/video.mp4"></video>
  </media-container>
</video-player>
```

The `defaultPlaybackRates` property also takes an array, such as `player.defaultPlaybackRates = [1, 2]`. Removing the attribute restores the defaults.
</FrameworkCase>

The button cycles through the rates in the order you list them, and the menu shows them in that order. `speedUp` and `speedDown` move to the next faster or slower rate whatever the order, and do nothing at the fastest or slowest rate. The player ignores values that aren't positive numbers, and repeated rates. If nothing usable is left, it falls back to the defaults.

### Rates for one control

To give one control a different list, set `rates` on it. The rest of the player keeps the default list. The control offers these rates as given, even ones outside the media's range, which play at the nearest end of the range.

<FrameworkCase frameworks={["react"]}>
```tsx
<PlaybackRateButton rates={[1, 1.5, 2]} />
```
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
```html
<media-playback-rate-button rates="1 1.5 2"></media-playback-rate-button>
```
</FrameworkCase>

To make the speed hotkeys change speed in fixed steps instead, give `speedUp` and `speedDown` a `value`. A `value` of `0.1` moves from `1` to `1.1`, then `1.2`, and so on.

### Rates outside the list

The media owns the current rate, so it can be one the menu doesn't offer, such as `1.1` set through the media API or a stepped hotkey. The menu then shows that rate as an extra item, slotted before the next faster rate. Skins set it in italics, and its accessible name is "Custom, 1.1×". The item goes away once the rate is back on the list. Normal speed (`1`) is added the same way when your list leaves it out, but isn't marked custom.

### Media range

Each media accepts rates within a range. Browsers play `0.0625` through `16`, YouTube `0.25` through `2`, and Vimeo up to `2`. The player leaves out any `defaultPlaybackRates` outside that range and keeps the rest in your order. If none are left, it offers the defaults within the range and warns in development. `setPlaybackRate` clamps a rate outside the range to the nearest end, and warns in development. That includes `0`, which would stop the picture while the player still reports playback; call `pause()` instead.

`playbackRates` lists rates even for a media that can't change its rate, so check `playbackRateAvailability` before offering them.

YouTube rounds rates down to a step of `0.05`, so asking for `1.13` plays at `1.1`.

### Selector

<FrameworkCase frameworks={["react"]}>
Pass `selectPlaybackRate` to <DocsLink slug="reference/api/use-player">`usePlayer`</DocsLink> to subscribe to playback rate state. Returns `undefined` if the playback rate feature is not configured.

Check `playbackRateAvailability` before showing a playback rate control.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
Pass `selectPlaybackRate` to <DocsLink slug="reference/api/player-controller">`PlayerController`</DocsLink> to subscribe to playback rate state. Returns `undefined` if the playback rate feature is not configured.

Check `playbackRateAvailability` before showing a playback rate control.
</FrameworkCase>

<FrameworkCase frameworks={["react"]}>
```tsx title="RateDisplay.tsx"
import { selectPlaybackRate, usePlayer } from '@videojs/react';

function RateDisplay() {
  const rate = usePlayer(selectPlaybackRate);
  if (!rate || rate.playbackRateAvailability !== 'available') return null;

  return <span>{rate.playbackRate}x</span>;
}
```
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
```ts title="rate-display.ts"
import { createPlayer, UIElement, selectPlaybackRate } from '@videojs/html';
import { videoFeatures } from '@videojs/html/video';

const { PlayerController } = createPlayer({ features: videoFeatures });

class RateDisplay extends UIElement {
  readonly #rate = new PlayerController(this, selectPlaybackRate);
}
```
</FrameworkCase>
