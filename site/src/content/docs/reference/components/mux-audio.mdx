Audio component for Mux-hosted streams. Give it a playback ID and it builds the stream URL, and it plays signed assets from their tokens. It plays through SPF, Video.js's own engine, or through hls.js like the <DocsLink slug="reference/components/hlsjs-video">hls.js video component</DocsLink>, depending on which entry point you import. For video, use the <DocsLink slug="reference/components/mux-video">Mux video component</DocsLink>. Start with <DocsLink slug="guides/mux">Play Mux videos</DocsLink> for playback IDs and signed playback, then add <DocsLink slug="guides/mux-data">Mux Data</DocsLink> to monitor playback.

## Import

<MediaImports media="mux-audio" package="@videojs/mux-audio" react="MuxAudio" />

The Mux audio component plays through one of two engines, chosen by import path: SPF, Video.js's own engine, or hls.js. The default import uses hls.js today and will switch to SPF in an upcoming release.

| Import | Engine |
|---|---|
| `.../media/mux-audio/spf` | SPF |
| `.../media/mux-audio` | hls.js today, SPF in an upcoming release |
| `.../media/mux-audio/hls-js` | hls.js |

<FrameworkCase frameworks={["react"]}>
```tsx
import { MuxAudio } from '@videojs/react/media/mux-audio/spf';
```

All three imports give you a `MuxAudio` component with the same basic API.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
```ts
import '@videojs/html/media/mux-audio/spf';
```

All three imports register the same `<mux-audio>` tag with the same basic API. Load only one of them on a page: the first one to load claims the tag, and the others are ignored.
</FrameworkCase>

<DocsLink slug="guides/mux" anchor="choose-a-playback-engine">Play Mux videos</DocsLink> covers when to use each engine.
