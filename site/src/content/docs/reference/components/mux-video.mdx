Video element for playing Mux-hosted HLS streams. It builds the stream URL, poster, and storyboard from a Mux playback ID, and plays the stream through the Video.js streaming engine (SPF). An [hls.js flavor](#choose-a-playback-engine) is available from a separate import.

## Import

<MediaImports media="mux-video" package="@videojs/mux-video" react="MuxVideo" />

## Choose a playback engine

The import path picks the engine. Both paths give you the same Mux video component with the same Mux source fields, posters, and storyboards.

<FrameworkCase frameworks={["react"]}>
| Import | Engine |
|---|---|
| `@videojs/react/media/mux-video` | SPF, the Video.js streaming engine. The default. |
| `@videojs/react/media/mux-video/hls-js` | [hls.js](https://github.com/video-dev/hls.js/) |

`@videojs/react/media/mux-video/spf` is the same module as the default, for code that wants to name the engine.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
| Import | CDN bundle | Engine |
|---|---|---|
| `@videojs/html/media/mux-video` | `media/mux-video.js` | SPF, the Video.js streaming engine. The default. |
| `@videojs/html/media/mux-video/hls-js` | `media/mux-video/hls-js.js` | [hls.js](https://github.com/video-dev/hls.js/) |

`@videojs/html/media/mux-video/spf` is the same module as the default, for code that wants to name the engine. Every flavor registers `<mux-video>`, and the first registration on a page wins, so load one.
</FrameworkCase>

### What the default engine plays

The default engine plays through Media Source Extensions (MSE). It plays:

- On-demand assets, packaged as CMAF or as MPEG-TS. Mux packages basic- and premium-quality assets as CMAF and plus-quality assets as MPEG-TS, and the engine converts MPEG-TS segments to fMP4 in the browser.
- Live streams packaged as CMAF, which is how Mux packages low-latency streams. They play at standard latency.
- [Signed playback](#signed-playback) and [DRM](#protected-content) with FairPlay, Widevine, and PlayReady.

Its `source` carries Mux fields only: `playbackId`, `customDomain`, `playback`, `poster`, `storyboard`, `drm`, and `src`. The engine takes no configuration from the source.

Three limits are worth knowing before you ship:

- It needs `MediaSource` or `ManagedMediaSource`. It has no native HLS fallback, so it cannot play in a browser that has neither.
- It treats every `src` as HLS. It won't play an MP4 URL.
- Its MPEG-TS support is a narrow subset: on-demand streams with H.264 video and AAC-LC audio. It has been verified in Chromium browsers only, so test plus-quality assets in the other browsers you support.

### When to use the hls.js flavor

Import the `hls-js` flavor when your player needs something from this list:

| You need | Why |
|---|---|
| hls.js configuration, or the hls.js instance | `source.engine` exists only on this flavor, and its `engine` property is the hls.js instance. On the default, `engine` is the SPF engine. |
| Native HLS playback | `source.preferPlayback` exists only on this flavor. It also falls back to the browser's HLS support where MSE is missing. |
| A client-side rendition cap | `source.maxAutoResolution`, `source.minAutoResolution`, and `source.capRenditionToPlayerSize` exist only on this flavor. `playback.maxResolution`, which asks Mux to trim the manifest, works on both. |
| A non-HLS `src` | `source.type` exists only on this flavor. |
| Low-latency live | The default plays a low-latency stream at standard latency. |
| Live streams in MPEG-TS | Mux packages standard- and reduced-latency live streams as MPEG-TS, and the default's MPEG-TS support covers on-demand only. |
| DVR live streams | The default does not play them reliably yet. |
| CEA-608 or CEA-708 captions, or ID3 timed metadata | The default reads neither from the stream. WebVTT subtitles in the manifest work on both. |
| AES-128 encrypted segments | The default does not decrypt them. |
| Engine-level <DocsLink slug="guides/mux-data">Mux Data</DocsLink> metrics | Mux Data hooks hls.js for rendition switches, request timing, and engine errors. The default reports the metrics the media element provides. |

The props, attributes, and events listed under [API Reference](#api-reference) describe the default flavor. The hls.js flavor adds the source fields above; <DocsLink slug="guides/media-sources">Media sources</DocsLink> documents them.

In TypeScript, `@videojs/mux-video` exports the default's source type as `MuxSourceBase`. The wider `MuxSource` type, with the hls.js fields, comes from `@videojs/mux-video/hls-js`.

## Load a source

<FrameworkCase frameworks={["react"]}>
The `source` param builds the URL for you from a playback ID, an optional custom domain, and `playback` params. Playback params are just camelCased [Mux playback query params](https://www.mux.com/docs/api-reference/stream/streaming/get-hls-manifest); for example, `max_resolution` becomes `maxResolution`.

```tsx
<MuxVideo
  source={{ 
    playbackId: 'BV3YZtogl89mg9VcNBhhnHm02Y34zI1nlMuMQfAbl3dM',
    customDomain: 'media.example.com',
    playback: { maxResolution: '1080p' }
  }} 
/>
```

If for some reason you need a bit more control, you can use the `src` param with a plain 'ol URL, too:

```tsx
<MuxVideo
  src="https://stream.mux.com/BV3YZtogl89mg9VcNBhhnHm02Y34zI1nlMuMQfAbl3dM.m3u8"
/>
```

MuxVideo ignores the same source object when it is assigned again. A new object fires `sourcechange` even when its values are equal, although an equivalent playback source does not reload.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>

`<mux-video>` takes Mux content two ways: a stream URL through `src`, or a structured `source` object.

```html
<mux-video src="https://stream.mux.com/BV3YZtogl89mg9VcNBhhnHm02Y34zI1nlMuMQfAbl3dM.m3u8"></mux-video>
```

The `source` object builds the URL for you from a playback ID, an optional custom domain, and `playback` params. Playback params are just camelCased [Mux playback query params](https://www.mux.com/docs/api-reference/stream/streaming/get-hls-manifest); for example, `max_resolution` becomes `maxResolution`.

```ts
const video = document.querySelector('mux-video')!;
video.source = {
  playbackId: 'BV3YZtogl89mg9VcNBhhnHm02Y34zI1nlMuMQfAbl3dM',
  customDomain: 'media.example.com',
  playback: { maxResolution: '1080p' },
};
```

`<mux-video>` ignores the same source object when it is assigned again. A new object fires `sourcechange` even when its values are equal, although an equivalent playback source does not reload.
</FrameworkCase>

## Posters and storyboards

The Mux video component derives a poster image and a storyboard from the playback ID. `source.poster` and `source.storyboard` configure the generated URLs.

When the Mux video component is inside a player, it supplies the poster for the skin to display. Set `poster` on the player when you want to use your own image instead.

<FrameworkCase frameworks={["react"]}>
A generated poster becomes available after MuxVideo mounts. Pass `poster` to the player when the image must appear in server-rendered HTML.
</FrameworkCase>

The Mux video component injects the derived storyboard `<track>` automatically and removes it when the media detects a live stream. Configure the derived URLs through the source object:

<FrameworkCase frameworks={["react"]}>
```tsx
<MuxVideo
  source={{
    playbackId: 'BV3YZtogl89mg9VcNBhhnHm02Y34zI1nlMuMQfAbl3dM',
    poster: { time: 2, width: 1280 },
    storyboard: { format: 'webp' },
  }}
/>
```
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
```ts
const video = document.querySelector('mux-video')!;
video.source = {
  playbackId: 'BV3YZtogl89mg9VcNBhhnHm02Y34zI1nlMuMQfAbl3dM',
  poster: { time: 2, width: 1280 },
  storyboard: { format: 'webp' },
};
```

For declarative HTML, `poster-time="2"` reflects to `source.poster.time` after the `src` attribute is parsed.
</FrameworkCase>

The storyboard lives on a Mux domain, so the Mux video component has to be CORS-enabled for that cross-origin `<track>` to load at all. The <DocsLink slug="reference/components/thumbnail">thumbnail component</DocsLink> then fetches the sprite sheets its cues point at the same way:

<FrameworkCase frameworks={["react"]}>
```tsx
<MuxVideo
  source={{ playbackId: 'BV3YZtogl89mg9VcNBhhnHm02Y34zI1nlMuMQfAbl3dM' }}
  crossOrigin="anonymous"
/>
```
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
```html
<mux-video
  src="https://stream.mux.com/BV3YZtogl89mg9VcNBhhnHm02Y34zI1nlMuMQfAbl3dM.m3u8"
  crossorigin="anonymous"
></mux-video>
```
</FrameworkCase>

## Signed playback

For [signed playback](https://www.mux.com/docs/guides/secure-video-playback), put the playback token on `source.playback.token`. The token replaces every other playback param, so bake modifiers like resolution and time bounds into the token when you sign it.

Signed playback needs a separate token for each image URL. Put the thumbnail token (`aud: 't'`) at `source.poster.token` and the storyboard token (`aud: 's'`) at `source.storyboard.token`. If either token is missing or has the wrong audience, the Mux video component does not generate the corresponding URL.

<FrameworkCase frameworks={["react"]}>
```tsx
<MuxVideo
  source={{
    playbackId: 'BV3YZtogl89mg9VcNBhhnHm02Y34zI1nlMuMQfAbl3dM',
    playback: { token: playbackToken },
    poster: { token: posterToken },
    storyboard: { token: storyboardToken },
  }}
/>
```
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
```ts
const video = document.querySelector('mux-video')!;
video.source = {
  playbackId: 'BV3YZtogl89mg9VcNBhhnHm02Y34zI1nlMuMQfAbl3dM',
  playback: { token: playbackToken },
  poster: { token: posterToken },
  storyboard: { token: storyboardToken },
};
```
</FrameworkCase>

## Protected content

For [DRM-protected](https://www.mux.com/docs/guides/protect-videos-with-drm) playback, put the DRM license token on `source.drm.token`. The Mux video component derives the FairPlay, Widevine, and PlayReady license servers from it. DRM playback is always signed, so a `playback.token` belongs alongside it.

<FrameworkCase frameworks={["react"]}>
```tsx
<MuxVideo
  source={{
    playbackId: 'BV3YZtogl89mg9VcNBhhnHm02Y34zI1nlMuMQfAbl3dM',
    playback: { token: playbackToken },
    drm: { token: drmToken },
  }}
/>
```
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
```ts
const video = document.querySelector('mux-video')!;
video.source = {
  playbackId: 'BV3YZtogl89mg9VcNBhhnHm02Y34zI1nlMuMQfAbl3dM',
  playback: { token: playbackToken },
  drm: { token: drmToken },
};
```
</FrameworkCase>

## Analytics and casting

The Mux video component plays Mux streams. It doesn't monitor them or cast them — <DocsLink slug="guides/mux-data">Mux Data</DocsLink> and <DocsLink slug="guides/casting">Google Cast</DocsLink> are separate extensions you add to the player alongside it. Mux Data needs no environment key here, since Mux attributes the views to the environment that owns the playback ID:

Install both extensions before using the example below:

```bash
pnpm add @videojs/mux-data @videojs/google-cast
```

<FrameworkCase frameworks={["react"]}>
```tsx
import { createPlayer } from '@videojs/react';
import { GoogleCast } from '@videojs/react/extensions/google-cast';
import { MuxData } from '@videojs/react/extensions/mux-data';
import { MuxVideo } from '@videojs/react/media/mux-video';
import { videoFeatures } from '@videojs/react/video';

const { Player } = createPlayer({ features: videoFeatures });

export function MuxPlayer() {
  return (
    <Player>
      <MuxVideo source={{ playbackId: 'BV3YZtogl89mg9VcNBhhnHm02Y34zI1nlMuMQfAbl3dM' }} playsInline />
      <MuxData playerSoftwareName="mux-video" />
      <GoogleCast />
    </Player>
  );
}
```
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
```html
<script type="module">
  import '@videojs/html/video/player';
  import '@videojs/html/media/mux-video';
  import '@videojs/html/extensions/mux-data';
  import '@videojs/html/extensions/google-cast';
</script>

<video-player>
  <mux-video src="https://stream.mux.com/BV3YZtogl89mg9VcNBhhnHm02Y34zI1nlMuMQfAbl3dM.m3u8" playsinline></mux-video>
  <mux-data player-software-name="mux-video"></mux-data>
  <google-cast></google-cast>
</video-player>
```
</FrameworkCase>
