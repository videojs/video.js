Adds the [Mux Data](https://data.mux.com) <DocsLink slug="guides/architecture">extension</DocsLink> to the player. It renders nothing — place it anywhere inside the player, and it follows whatever media the player attaches. See <DocsLink slug="guides/mux-data">Mux Data</DocsLink> for how monitoring works.

## Options

<FrameworkCase frameworks={["react"]}>
| Prop | Type | Description |
|---|---|---|
| `envKey` | `string` | Mux Data environment key the beacons are sent to. Optional for Mux-hosted playback |
| `metadata` | `object` | Mux Data metadata for the view |
| `playerSoftwareName` | `string` | Player name reported to Mux Data. Defaults to `videojs-react-<engine>`; see [Player software name](#player-software-name) |
| `playerSoftwareVersion` | `string` | Player version reported to Mux Data. Defaults to the Video.js version |
| `playerInitTime` | `number` | Epoch milliseconds the player was initialized. Defaults to when the player was created |
| `beaconCollectionDomain` | `string` | Custom domain the beacons are sent to |
| `disableCookies` | `boolean` | Stops the SDK from setting cookies |
| `debug` | `boolean` | Turns on SDK debug logging |
| `MuxDataSdk` | `object` | SDK used for monitoring. Set it to `undefined` to switch monitoring off |
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
| Attribute | Property | Description |
|---|---|---|
| `env-key` | `envKey` | Mux Data environment key the beacons are sent to. Optional for Mux-hosted playback |
| — | `metadata` | Mux Data metadata for the view |

| `player-software-version` | `playerSoftwareVersion` | Player version reported to Mux Data. Defaults to the Video.js version |

| `beacon-collection-domain` | `beaconCollectionDomain` | Custom domain the beacons are sent to |
| `disable-cookies` | `disableCookies` | Stops the SDK from setting cookies |
| `debug` | `debug` | Turns on SDK debug logging |
| — | `MuxDataSdk` | SDK used for monitoring. Set it to `undefined` to switch monitoring off |

</FrameworkCase>

Views also report the extension itself as the Mux plugin, so they can be told apart from other Video.js integrations such as `videojs-mux`.

## Player software name

When no player software name is set, views report `videojs-<framework>-<engine>`, where the framework is `html` or `react` and the engine is the one playing the current source:

| Engine | Played by |
|---|---|
| `hlsjs` | hls.js |
| `spf` | The Video.js SPF engine |
| `shaka` | Shaka Player |
| `dashjs` | dash.js |
| `browser` | The browser itself, like native HLS in Safari or an MP4 file |

The name updates on the current view when a source change switches engines. Media that doesn't declare an engine name leaves it out, as in `videojs-html`. A player software name you set always takes precedence.

The player software version defaults to the Video.js version, and the Mux plugin is reported as `@videojs/mux-data` at the same version.

Changing `MuxDataSdk`, `beaconCollectionDomain`, `debug`, or `disableCookies` restarts monitoring, which ends the current view and starts a new one. The rest update the view in place.
