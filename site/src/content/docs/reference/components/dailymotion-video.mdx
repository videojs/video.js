The Dailymotion player plays videos inside a player configuration you create in [Dailymotion Studio](https://www.dailymotion.com/partner/embed/players), and this component drives it through the [Dailymotion Web SDK](https://developers.dailymotion.com/reference/web-sdk-player-methods). Dailymotion refuses any embed that doesn't name a player configuration, so every source carries a Player ID. See [Create a Player](https://developers.dailymotion.com/docs/create-a-player) in the official Dailymotion documentation.

## Load a source

The simplest `src` is the player embed URL Dailymotion Studio gives you, which names both the player configuration and the video:

<FrameworkCase frameworks={["react"]}>
```tsx
<DailymotionVideo src="https://geo.dailymotion.com/player/x8lr5.html?video=x84sh87" />
```
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
```html
<dailymotion-video src="https://geo.dailymotion.com/player/x8lr5.html?video=x84sh87"></dailymotion-video>
```
</FrameworkCase>

### Specify the Player ID

Video page URLs (`dailymotion.com/video/<id>`), legacy embed URLs (`dailymotion.com/embed/video/<id>`, or `geo.dailymotion.com/player.html?video=<id>`, where they now redirect), and short links (`dai.ly/<id>`) name no player configuration, so pair them with `engine.dailymotion.player`. It also wins over the configuration a player embed URL names:

<FrameworkCase frameworks={["react"]}>
```tsx
<DailymotionVideo
  source={{
    src: 'https://www.dailymotion.com/video/x84sh87',
    engine: { dailymotion: { player: 'x8lr5' } },
  }}
/>
```
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
```ts
const video = document.querySelector('dailymotion-video');
video.source = {
  src: 'https://www.dailymotion.com/video/x84sh87',
  engine: { dailymotion: { player: 'x8lr5' } },
};
```
</FrameworkCase>

Without a Player ID, the component reports a `MEDIA_ERR_SRC_NOT_SUPPORTED` error instead of creating a player Dailymotion would reject. The SDK script is loaded from `geo.dailymotion.com` with the first player created on the page.

## Configure the player in Dailymotion Studio

The player configuration decides what the embed can't change at runtime. To use the component under a <DocsLink slug="guides/skins">player skin</DocsLink>, set these in the player's settings:

| Setting | Recommended | Why |
|---|---|---|
| Playback controls | Off | Otherwise Dailymotion's controls show under the skin. Without `controls`, the component keeps the player from taking pointer input so the skin can respond to hover, but it can't hide Dailymotion's controls. |
| Controls during ads | Off | Same as playback controls, while an ad plays. |
| Autostart | Off | `autoplay` starts a player the configuration leaves stopped, but it can't stop one the configuration starts. In development, the component logs a warning when the configuration starts playback while `autoplay` is off. |
| Spinner | Off | The skin shows its own buffering indicator. |
| Autonext | Off | Without `controls`, its "Up next" card at the end can't be clicked or closed: clicks reach the skin, which replays the video. When the player moves on to the next video by itself, `src` still names the one you loaded. |
| Picture-in-picture | Off | Dailymotion's picture-in-picture moves the player out of the element, away from the skin. |
| Keyboard shortcuts | Off | The skin's hotkeys handle playback. |

## Behavior

- Volume and mute both work, like a native `<video>`. Dailymotion has no separate mute, so muting sets its volume to `0` and unmuting restores the previous level.
- `playbackRate` takes Dailymotion's rates, `0.25` to `2` in steps of `0.25`. Dailymotion rounds any other value up to the next one and caps it at `2`, and `playbackRate` then reports the rate it plays at.
- `loop` is passed to Dailymotion, which restarts the video itself.
- Changing `src` loads the new video into the same player. Changing the player configuration or other `engine.dailymotion` options creates a new player, since Dailymotion only reads them when a player is created. So does autoplay, but only at the next load: call load() to apply a change right away. `muted` and `loop` change in place.
- Seeking before the video has started, or after it has ended, also starts playback. Dailymotion does this itself; a native `<video>` would stay paused. Seeking while paused mid-video stays paused.
- The SDK reports no buffered range, so `buffered` ends at the current time.
- Ads play inside the embed. `paused` follows the ad while it plays, but `currentTime` and `duration` always describe the video.
- When the browser refuses to start playback, as it does for unmuted autoplay, the component reports `pause` instead of playing.
- Fullscreen targets the element the player is built in.
- `poster`, `preload`, and `playsinline` are accepted for parity with `<video>` but have no effect: the player configuration decides them.
