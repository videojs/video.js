## How it works

The <DocsLink slug="reference/api/feature-fullscreen">fullscreen feature</DocsLink> tracks fullscreen state and provides the actions:

- `isFullscreen` is `true` while the player is fullscreen, from any path — your button, native controls, or the platform presentation.
- `fullscreenAvailability` is `'available'`, `'unavailable'`, or `'unsupported'`. It starts as `'unavailable'`, then settles to `'available'` or `'unsupported'` when the feature attaches to a media element.
- `requestFullscreen()` and `exitFullscreen()` change the presentation. When the Fullscreen API is available, requests target the player container. Otherwise they fall back to the media element's native presentation.

Fullscreen and picture-in-picture are exclusive: requesting fullscreen exits an active picture-in-picture presentation first.

Style fullscreen state through the container's `:fullscreen` pseudo-class, the button's `data-fullscreen` attribute, or `isFullscreen` in player state.

The built-in button hides when `fullscreenAvailability` is not `'available'`. Use the same check for custom controls and handle rejected requests. When the attached media has no supported fullscreen method, the action resolves without changing the presentation.

## Availability and constraints

- Fullscreen requests must come from a user gesture; browsers reject requests outside one.
- iPhone Safari has no element Fullscreen API. The player falls back to the video's native fullscreen presentation, which shows the system player UI instead of your custom controls. iPads support element fullscreen.
- Orientation locking requires the Screen Orientation API with lock support — in practice, Android browsers in fullscreen. iOS doesn't support programmatic orientation lock.
- Inside iframes, fullscreen needs `allow="fullscreen"` on the embedding iframe.

## Common variations

### Lock orientation while fullscreen

<FrameworkCase frameworks={["react"]}>

Add `orientationLockFeature` to lock screen orientation while the player is fullscreen. It isn't part of `videoFeatures`, so the preset `VideoPlayer` doesn't include it. It locks to `landscape` by default and unlocks on exit.

The preset has a fixed feature list, so build the player yourself with <DocsLink slug="reference/api/create-player">`createPlayer`</DocsLink>:

```tsx
import { Container, createPlayer, FullscreenButton, orientationLockFeature } from '@videojs/react';
import { Video, videoFeatures } from '@videojs/react/video';

const { Player } = createPlayer({
  features: [...videoFeatures, orientationLockFeature],
});

export default function App() {
  return (
    <Player>
      <Container>
        <Video src="https://stream.mux.com/BV3YZtogl89mg9VcNBhhnHm02Y34zI1nlMuMQfAbl3dM/highest.mp4" muted playsInline />
        <FullscreenButton>Fullscreen</FullscreenButton>
      </Container>
    </Player>
  );
}
```

</FrameworkCase>
<FrameworkCase frameworks={["html"]}>

Add `orientationLockFeature` to lock screen orientation while the player is fullscreen. It isn't part of `videoFeatures`, so the preset `<video-player>` doesn't include it. It locks to `landscape` by default and unlocks on exit.

Register a custom player tag with <DocsLink slug="reference/api/html-create-player">`createPlayer`</DocsLink>:

```html
<orientation-player>
  <media-container>
    <video src="https://stream.mux.com/BV3YZtogl89mg9VcNBhhnHm02Y34zI1nlMuMQfAbl3dM/highest.mp4" muted playsinline></video>
    <media-fullscreen-button>Fullscreen</media-fullscreen-button>
  </media-container>
</orientation-player>
<script type="module">
  import { createPlayer, orientationLockFeature } from '@videojs/html';
  import { videoFeatures } from '@videojs/html/video';
  import '@videojs/html/ui/container';
  import '@videojs/html/ui/fullscreen-button';

  const { PlayerElement } = createPlayer({
    features: [...videoFeatures, orientationLockFeature],
  });

  customElements.define('orientation-player', PlayerElement);
</script>
```

</FrameworkCase>

### Double-click to toggle

<FrameworkCase frameworks={["react"]}>

Use the `Gesture` component — the packaged skins ship this exact binding. Keep the button as the accessible path; gestures are a pointer-only shortcut.

```tsx
import { Gesture } from '@videojs/react';

<Gesture type="doubletap" action="toggleFullscreen" region="center" />
```

</FrameworkCase>
<FrameworkCase frameworks={["html"]}>

Use the `<media-gesture>` element — the packaged skins ship this exact binding. Keep the button as the accessible path; gestures are a pointer-only shortcut.

```html
<media-gesture type="doubletap" action="toggleFullscreen" region="center"></media-gesture>
<script type="module">
  import '@videojs/html/ui/gesture';
</script>
```

</FrameworkCase>

With left, center, and right double-tap bindings for the same pointer type, `region="center"` covers the middle third, as in the on-demand video skins. A center-only double-tap binding covers the whole surface. See <DocsLink slug="guides/keyboard-shortcuts">Add keyboard shortcuts and gestures</DocsLink> for region behavior.

## Troubleshooting

### The fullscreen button doesn't render

The button hides while `fullscreenAvailability` is `'unavailable'` or `'unsupported'`. Wait for media attachment, check browser support, and confirm that an embedding iframe permits fullscreen with `allow="fullscreen"`.

### The fullscreen request is rejected

Call the action directly from a click handler and check that an embedding iframe permits fullscreen with `allow="fullscreen"`. Handle the returned promise's rejection. To detect unsupported fullscreen, check `fullscreenAvailability`; an unsupported request can resolve without entering fullscreen.

### Custom controls disappear in fullscreen on iPhone

Expected: iPhone Safari uses the native video presentation, which replaces custom UI with system controls. Design mobile controls assuming this fallback.

### Orientation doesn't lock

Orientation lock works in fullscreen on Android browsers; iOS doesn't support it. Confirm `orientationLockFeature` is in your feature list.
