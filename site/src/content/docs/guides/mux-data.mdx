[Mux Data](https://www.mux.com/data) measures playback quality: startup time, rebuffering, playback failures, and watch time. Add the Mux Data <DocsLink slug="guides/architecture">extension</DocsLink> to a player and it monitors whichever media that player is playing.

## Installation

<FrameworkCase frameworks={["react"]}>
Install the extension alongside the framework façade. The example below also installs the Mux playback adapter for MuxVideo:

```bash
pnpm add @videojs/react @videojs/mux-video @videojs/mux-data
```
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
Install the extension alongside the framework façade. The example below also installs the Mux playback adapter for `<mux-video>`:

```bash
pnpm add @videojs/html @videojs/mux-video @videojs/mux-data
```
</FrameworkCase>

## Recommended approach

Put the extension inside the player next to the media. It renders nothing, so its position doesn't matter:

<FrameworkCase frameworks={["react"]}>
```tsx title="App.tsx"
import { Container, createPlayer } from '@videojs/react';
import { MuxData } from '@videojs/react/extensions/mux-data';
import { MuxVideo } from '@videojs/react/media/mux-video';
import { videoFeatures } from '@videojs/react/video';

const { Player } = createPlayer({ features: videoFeatures });

export default function App() {
  return (
    <Player>
      <Container>
        <MuxVideo source={{ playbackId: 'BV3YZtogl89mg9VcNBhhnHm02Y34zI1nlMuMQfAbl3dM' }} playsInline />
        <MuxData metadata={{ video_title: 'Big Buck Bunny' }} /> {/* [!code focus] */}
      </Container>
    </Player>
  );
}
```
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
```html title="index.html"
<video-player>
  <media-container>
    <mux-video src="https://stream.mux.com/BV3YZtogl89mg9VcNBhhnHm02Y34zI1nlMuMQfAbl3dM.m3u8" playsinline></mux-video>
    <mux-data metadata-video-title="Big Buck Bunny"></mux-data> <!-- [!code focus] -->
  </media-container>
</video-player>
<script type="module">
  import '@videojs/html/video/player';
  import '@videojs/html/ui/container';
  import '@videojs/html/media/mux-video';
  import '@videojs/html/extensions/mux-data';
</script>
```
</FrameworkCase>

That's the whole setup for Mux-hosted playback. You don't need an environment key, and the title is optional but makes views easier to find in the dashboard.

## How it works

<FrameworkCase frameworks={["react"]}>
The extension attaches to the media the player is using, not to a specific element type, so it monitors <DocsLink slug="reference/components/mux-video">MuxVideo</DocsLink>, <DocsLink slug="reference/components/hlsjs-video">HlsJsVideo</DocsLink>, <DocsLink slug="reference/components/dash-video">DashVideo</DocsLink>, and the rest alike. When the source changes, it follows.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
The extension attaches to the media the player is using, not to a specific element type, so it monitors <DocsLink slug="reference/components/mux-video">`<mux-video>`</DocsLink>, <DocsLink slug="reference/components/hlsjs-video">`<hlsjs-video>`</DocsLink>, <DocsLink slug="reference/components/dash-video">`<dash-video>`</DocsLink>, and the rest alike. When the source changes, it follows.
</FrameworkCase>

How much it reports depends on the engine playing the stream; the <DocsLink slug="reference/components/mux-data" anchor="engine-data">MuxData reference</DocsLink> lists what each engine adds.

Mux needs to know which environment each view belongs to. For a source on `stream.mux.com`, the extension reports the playback ID, and Mux files the view under the environment that owns it. Any other source needs an environment key.

## Availability and constraints

- Mux Data is opt-in. No media component monitors playback on its own, Mux ones included, so nothing is measured and no beacons are sent until you add the extension.
- Sources Mux doesn't host, like a self-hosted HLS or DASH stream, need `envKey`. See [Monitor a source Mux doesn't host](#monitor-a-source-mux-doesnt-host).
- Iframe embeds such as YouTube and Vimeo can't be monitored, and some engines report less detail than others. See which <DocsLink slug="reference/components/mux-data" anchor="engine-data">engines report what</DocsLink>.

## Common variations

### Monitor a source Mux doesn't host

Find the environment key in the [Mux dashboard](https://dashboard.mux.com/settings/data) and set `envKey`. This example plays the stream with the hls.js adapter:

<FrameworkCase frameworks={["react"]}>
```bash
pnpm add @videojs/react @videojs/hlsjs-video @videojs/mux-data
```

```tsx title="App.tsx"
import { Container, createPlayer } from '@videojs/react';
import { MuxData } from '@videojs/react/extensions/mux-data';
import { HlsJsVideo } from '@videojs/react/media/hlsjs-video';
import { videoFeatures } from '@videojs/react/video';

const { Player } = createPlayer({ features: videoFeatures });

export default function App() {
  return (
    <Player>
      <Container>
        <HlsJsVideo src="https://example.com/stream.m3u8" playsInline />
        <MuxData envKey="YOUR_ENV_KEY" /> {/* [!code focus] */}
      </Container>
    </Player>
  );
}
```
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
```bash
pnpm add @videojs/html @videojs/hlsjs-video @videojs/mux-data
```

```html title="index.html"
<video-player>
  <media-container>
    <hlsjs-video src="https://example.com/stream.m3u8" playsinline></hlsjs-video>
    <mux-data env-key="YOUR_ENV_KEY"></mux-data> <!-- [!code focus] -->
  </media-container>
</video-player>
<script type="module">
  import '@videojs/html/video/player';
  import '@videojs/html/ui/container';
  import '@videojs/html/media/hlsjs-video';
  import '@videojs/html/extensions/mux-data';
</script>
```
</FrameworkCase>

An explicit `envKey` also overrides the environment Mux infers for Mux-hosted playback, so set one to send those views to a different environment.

### Describe the view

Pass Mux Data [metadata](https://www.mux.com/docs/guides/make-your-data-actionable-with-metadata) to label views with your own titles, viewer IDs, and custom dimensions:

<FrameworkCase frameworks={["react"]}>
```tsx
<MuxData metadata={{ video_title: 'Big Buck Bunny', viewer_user_id: 'u_789' }} />
```
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
```html
<mux-data
  metadata-video-title="Big Buck Bunny"
  metadata-viewer-user-id="u_789"
></mux-data>
```

To pass an object instead, assign the `metadata` property. It overrides attributes with the same key:

```ts
const muxData = document.querySelector('mux-data');
muxData.metadata = { video_title: 'Big Buck Bunny', viewer_user_id: 'u_789' };
```
</FrameworkCase>

### Report your own player name

<FrameworkCase frameworks={["react"]}>
By default, views report a player name built from the engine, such as `videojs-react-hlsjs`, so you can compare engines in Mux Data. To group views under your own name instead, set `playerSoftwareName`:

```tsx
<MuxData playerSoftwareName="my-player" playerSoftwareVersion="2.4.0" />
```
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
By default, views report a player name built from the engine, such as `videojs-html-hlsjs`, so you can compare engines in Mux Data. To group views under your own name instead, set `player-software-name`:

```html
<mux-data player-software-name="my-player" player-software-version="2.4.0"></mux-data>
```
</FrameworkCase>

The <DocsLink slug="reference/components/mux-data" anchor="player-software-name">player software name reference</DocsLink> lists every engine name.

## Troubleshooting

### No views appear for a self-hosted stream

Mux can only file views under an environment by playback ID when the source is on `stream.mux.com`. Set `envKey`.

### No views appear for a YouTube or Vimeo embed

Iframe embeds don't expose a media element for the Mux Data SDK to monitor, so the extension skips them.

### A view ends and a new one starts while the video plays

A few options restart monitoring when they change, which ends the current view. Set them once, before playback starts. See which <DocsLink slug="reference/components/mux-data" anchor="options-that-restart-monitoring">options restart monitoring</DocsLink>.

### You can't tell whether beacons are sent

Set `debug` to turn on the Mux Data SDK's console logging.
