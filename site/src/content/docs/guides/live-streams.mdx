## Recommended approach

<FrameworkCase frameworks={["react"]}>
Use the live feature bundle with a streaming media component, and give users a `LiveButton`: it shows whether playback is at the live edge and seeks back to it when activated.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
Use the live feature bundle with a streaming media component, and give users a `<media-live-button>`: it shows whether playback is at the live edge and seeks back to it when activated.
</FrameworkCase>

<FrameworkCase frameworks={["react"]}>

```tsx

import { LiveVideoPlayer } from '@videojs/react/live-video';
import { HlsJsVideo } from '@videojs/react/media/hlsjs-video';

export default function App() {
  return (
    <LiveVideoPlayer>
      <Container>
        <HlsJsVideo src="https://your-stream.example.com/live.m3u8" autoPlay muted playsInline />
        <LiveButton render={(props, state) => <button {...props}>{state.liveEdge ? 'LIVE' : 'Go live'}</button>} />
      </Container>
    </LiveVideoPlayer>
  );
}
```

## How it works

Two features describe liveness:

- The <DocsLink slug="reference/api/feature-stream-type">stream type feature</DocsLink> reports `streamType`: `'live'`, `'on-demand'`, or `'unknown'`. Streaming media derives it from manifest metadata; plain media elements fall back to duration-based detection. `liveVideoFeatures` does not include it; add `streamTypeFeature` to the player's features when you need `streamType`.
- The <DocsLink slug="reference/api/feature-live">live feature</DocsLink> reports two values:
  - `liveEdgeStart` is where "live" begins on the timeline. When the playhead is at or past this time, the viewer is watching live; behind it, they're watching earlier moments of the stream.
  - `targetLiveWindow` describes the kind of live window: `0` for a sliding window, `Infinity` for an event with playback history, and `NaN` for on-demand or unknown content. Read `seekable` to find the actual times viewers can rewind to.

The <DocsLink slug="reference/api/feature-time">time feature</DocsLink> replaces an infinite media duration with the end of the seekable range. That end advances as new segments become available; the start can also advance as old segments expire.

<FrameworkCase frameworks={["react"]}>
LiveButton treats playback as live when the playhead is no more than five seconds behind `liveEdgeStart`. If `liveEdgeStart` is unknown, the button uses the last ten seconds of the seekable range instead. When playback is farther behind, activating the button seeks to the seekable end. The button is disabled (`data-disabled`) when the media is not live or has no finite seekable end. At the edge, it is inactive (`aria-disabled="true"`).
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
`<media-live-button>` treats playback as live when the playhead is no more than five seconds behind `liveEdgeStart`. If `liveEdgeStart` is unknown, the button uses the last ten seconds of the seekable range instead. When playback is farther behind, activating the button seeks to the seekable end. The button is disabled (`data-disabled`) when the media is not live or has no finite seekable end. At the edge, it is inactive (`aria-disabled="true"`).
</FrameworkCase>

## Availability and constraints

- `liveEdgeStart` and `targetLiveWindow` require media that implements the live capability. Examples include <DocsLink slug="reference/components/hlsjs-video">hls.js video</DocsLink>, <DocsLink slug="reference/components/hls-video">SPF HLS video</DocsLink>, <DocsLink slug="reference/components/native-hls-video">native HLS video</DocsLink>, and <DocsLink slug="reference/components/shaka-video">Shaka video</DocsLink>. Native HLS video requires browser HLS support. A plain `<video>` can report a live `streamType` from its duration, but its live-window values stay `NaN`.
- Live playback drifts behind the edge when the network stalls or the tab is backgrounded. Always give users a path back to the edge.
- Both sliding live windows and growing event histories can support seeking. Check `seekable` for the available range. The built-in time slider starts at zero, so use it only while the seekable history starts at zero; a moving start requires a custom slider.
- `liveVideoFeatures` omits playback rate control. Add it explicitly if your DVR UI needs it.

## Common variations

### DVR: let users scrub back

<FrameworkCase frameworks={["react"]}>
For a live event whose seekable history starts at zero, add a <DocsLink slug="reference/components/time-slider">TimeSlider</DocsLink> to your custom UI or <DocsLink slug="guides/customize-skins" anchor="style-skin-source">customized live skin</DocsLink>. Its maximum follows the seekable end. For a sliding window whose start moves forward, build a slider from the current `seekable` start and end; the built-in slider would include expired times.

### Switch UI by stream type

Render live or on-demand controls from `streamType` when one player handles both kinds of content. Add `streamTypeFeature` to the player's features; `liveVideoFeatures` does not include it:

<FrameworkCase frameworks={["react"]}>

The preset `LiveVideoPlayer` comes with a fixed feature set. To change it, build the player yourself with <DocsLink slug="reference/api/create-player">`createPlayer`</DocsLink> — the escape hatch for custom feature sets:

```tsx
import { Container, createPlayer, LiveButton, streamTypeFeature } from '@videojs/react';
import { liveVideoFeatures } from '@videojs/react/live-video';
import { HlsJsVideo } from '@videojs/react/media/hlsjs-video';

const { Player, usePlayer } = createPlayer({ features: [...liveVideoFeatures, streamTypeFeature] });

function LiveBadge() {
  const streamType = usePlayer((s) => s.streamType);
  if (streamType !== 'live') return null;

  return <LiveButton render={(props, state) => <button {...props}>{state.liveEdge ? 'LIVE' : 'Go live'}</button>} />;
}

export default function App() {
  return (
    <Player>
      <Container>
        <HlsJsVideo src="https://your-stream.example.com/live.m3u8" autoPlay muted playsInline />
        <LiveBadge />
      </Container>
    </Player>
  );
}
```

</FrameworkCase>
<FrameworkCase frameworks={["html"]}>

`<media-live-button>` already reflects live state. To show a whole group of controls only for live streams, compose a custom player and subscribe to its store:

```html
<stream-type-player>
  <media-container>
    <hlsjs-video src="https://your-stream.example.com/live.m3u8" autoplay muted playsinline></hlsjs-video>
    <div id="live-controls" hidden>
      <media-live-button></media-live-button>
    </div>
  </media-container>
</stream-type-player>
<script type="module">
  import { createPlayer, selectStreamType, streamTypeFeature } from '@videojs/html';
  import { liveVideoFeatures } from '@videojs/html/live-video';
  import '@videojs/html/media/hlsjs-video';
  import '@videojs/html/ui/container';
  import '@videojs/html/ui/live-button';

  const { PlayerElement } = createPlayer({
    features: [...liveVideoFeatures, streamTypeFeature],
  });
  customElements.define('stream-type-player', PlayerElement);

  const player = document.querySelector('stream-type-player');
  const store = player.store;
  const controls = document.querySelector('#live-controls');
  const update = () => {
    controls.hidden = selectStreamType(store.state)?.streamType !== 'live';
  };

  const unsubscribe = store.subscribe(update);
  update();
  // Call unsubscribe() when this player is removed.
</script>
```

</FrameworkCase>

## Troubleshooting

### The live badge never activates

<FrameworkCase frameworks={["react"]}>
LiveButton reads `targetLiveWindow`, `currentTime`, and `seekable`. Confirm that `targetLiveWindow` is `0` or `Infinity` and that `seekable` has a finite end. Use a live-capable media component such as <DocsLink slug="reference/components/hlsjs-video">HlsJsVideo</DocsLink>. The live button does not need `streamTypeFeature`; add it only when your own UI reads `streamType`.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
`<media-live-button>` reads `targetLiveWindow`, `currentTime`, and `seekable`. Confirm that `targetLiveWindow` is `0` or `Infinity` and that `seekable` has a finite end. Use a live-capable media component such as <DocsLink slug="reference/components/hlsjs-video">`<hlsjs-video>`</DocsLink>. The live button does not need `streamTypeFeature`; add it only when your own UI reads `streamType`.
</FrameworkCase>

### Playback keeps falling behind the edge

<FrameworkCase frameworks={["react"]}>
Network throughput can't sustain the stream, or the tab was backgrounded. LiveButton returns users to the edge; for lower drift, review the stream's latency configuration on the encoder side.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
Network throughput can't sustain the stream, or the tab was backgrounded. `<media-live-button>` returns users to the edge; for lower drift, review the stream's latency configuration on the encoder side.
</FrameworkCase>

### The time slider behaves oddly on a live stream

Compare the slider's range with `seekable`. The built-in slider always starts at zero. Once a sliding window moves past zero, the slider's range includes expired history. Use a custom slider that follows both range bounds, or keep the live button without a timeline.
