## Recommended approach

<FrameworkCase frameworks={["react"]}>
Add a `<track kind="metadata" label="thumbnails" default>` whose cues reference storyboard images. Then put a slider thumbnail inside the <DocsLink slug="reference/components/time-slider">TimeSlider</DocsLink>. Scrubbing shows the frame under the pointer. The slider thumbnail reads the pointer time from the slider, so you never pass `time`; it otherwise accepts the same props as the standalone <DocsLink slug="reference/components/thumbnail">Thumbnail</DocsLink>.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
Add a `<track kind="metadata" label="thumbnails" default>` whose cues reference storyboard images. Then put a slider thumbnail inside the <DocsLink slug="reference/components/time-slider">`<media-time-slider>`</DocsLink>. Scrubbing shows the frame under the pointer. The slider thumbnail reads the pointer time from the slider, so you never pass `time`; it otherwise accepts the same attributes as the standalone <DocsLink slug="reference/components/thumbnail">`<media-thumbnail>`</DocsLink>.
</FrameworkCase>

<FrameworkCase frameworks={["react"]}>
Compose `Slider.Thumbnail.Root` around `Slider.Thumbnail.Image`, and put image settings such as `crossOrigin`, `loading`, and `fetchPriority` on the image part.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
`<media-slider-thumbnail>` draws its own image unless you supply an `<img>` child. Set `crossorigin`, `loading`, or `fetchpriority` on the element itself or on that image.
</FrameworkCase>

## How it works

<FrameworkCase frameworks={["react"]}>
- Previews come from a storyboard: a `kind="metadata"` text track labeled `thumbnails` whose WebVTT cues map time ranges to image URLs (optionally with sprite coordinates). The <DocsLink slug="reference/api/feature-text-tracks">text track feature</DocsLink> exposes this track as `thumbnailsTrack`, with its `cues` and `src`.
- The slider thumbnail renders the storyboard frame for the slider's pointer position. While the pointer is over the slider, the slider sets `data-pointing` and the `--media-slider-pointer` CSS variable; the example's CSS uses them to reveal the preview and position it over the pointer.
- To render a storyboard frame outside the slider — a fixed preview for a chapter list, for example — use the standalone <DocsLink slug="reference/components/thumbnail">Thumbnail</DocsLink> component with an explicit `time`.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
- Previews come from a storyboard: a `kind="metadata"` text track labeled `thumbnails` whose WebVTT cues map time ranges to image URLs (optionally with sprite coordinates). The <DocsLink slug="reference/api/feature-text-tracks">text track feature</DocsLink> exposes this track as `thumbnailsTrack`, with its `cues` and `src`.
- The slider thumbnail renders the storyboard frame for the slider's pointer position. While the pointer is over the slider, the slider sets `data-pointing` and the `--media-slider-pointer` CSS variable; the example's CSS uses them to reveal the preview and position it over the pointer.
- To render a storyboard frame outside the slider — a fixed preview for a chapter list, for example — use the standalone <DocsLink slug="reference/components/thumbnail">`<media-thumbnail>`</DocsLink> element with an explicit `time`.
</FrameworkCase>

Each cue's text is an image URL. An optional `#xywh=x,y,w,h` fragment crops one frame out of a sprite sheet:

```txt title="storyboard.vtt"
WEBVTT

00:00:00.000 --> 00:00:05.000
storyboard.jpg#xywh=0,0,256,160

00:00:05.000 --> 00:00:10.000
storyboard.jpg#xywh=256,0,256,160
```

## Availability and constraints

<FrameworkCase frameworks={["react"]}>
- Thumbnails require a storyboard asset generated alongside the media; the player doesn't extract frames from the video itself.
- Cross-origin storyboards need CORS headers, and `crossOrigin` on the media element for the track to load.
- Cues load asynchronously. The track appears before its cues are parsed, so previews fill in when the track finishes loading.
- Storyboard images download on demand; oversized sprite sheets hurt seek-preview responsiveness more than they help quality.
</FrameworkCase>

## Common variations

### Customize the skin's thumbnail image

<FrameworkCase frameworks={["react"]}>
Inside a packaged skin, pass `renderThumbnail` to draw the image yourself; the skin still supplies `src` and sizing:

```tsx
<VideoSkin renderThumbnail={<img alt="" loading="lazy" fetchPriority="low" />} />
```
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
Inside a packaged skin, an `<img slot="thumbnail">` replaces the image the skin carries, so image attributes go on it:

```html
<video-player>
  <video-skin>
    <video src="video.mp4" crossorigin="anonymous">
      <track kind="metadata" label="thumbnails" src="storyboard.vtt" default />
    </video>
    <img slot="thumbnail" alt="" loading="lazy" fetchpriority="low" />
  </video-skin>
</video-player>
<script type="module">
  import '@videojs/html/video/player';
  import '@videojs/html/video/skin';
</script>
```
</FrameworkCase>

## Troubleshooting

### Thumbnails don't appear while scrubbing

<FrameworkCase frameworks={["react"]}>
Confirm the storyboard track is `kind="metadata"` with `label="thumbnails"` and has the `default` attribute — the browser leaves a non-default track disabled and never loads its cues. Then confirm the VTT loads (network panel) and cross-origin assets have CORS headers with `crossOrigin` set on the media element.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
Confirm the storyboard track is `kind="metadata"` with `label="thumbnails"` and has the `default` attribute — the browser leaves a non-default track disabled and never loads its cues. Then confirm the VTT loads (network panel) and cross-origin assets have CORS headers with `crossorigin` set on the media element.
</FrameworkCase>

### Thumbnails are blurry or slow

Regenerate the storyboard with a larger frame size, or split giant sprite sheets into smaller images.
