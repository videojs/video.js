<Aside type="note" title="New in version 10">
In prior versions of Video.js, skins were CSS-only themes applied to the same set of default controls. In version 10 the concept of skins has been expanded to include the UI components, so each skin can be completely unique and only include the UI components it needs.
</Aside>

A skin wraps the media component and provides the player's complete interface. It combines a specific set of UI components with the styles that arrange and present them.

## Choose a skin

The video, audio, live video, and live audio presets each provide four skins: Default, Neutral, Compat, and Scaffold. Compare them on three questions: which features you need, how much of the design you want to bring, and how consistently the player should look across browsers.

| | Default | Neutral | Compat | Scaffold |
|---|---|---|---|---|
| Features | Complete | Same as Default | The same core controls in a simpler layout | Same as Compat |
| Styling | Opinionated and distinctly Video.js | Opinionated and easy to brand | Unbranded, a polished step above native controls | Unbranded and minimal, a foundation to restyle |
| Browser compatibility | Uses newer visual effects where browsers support them | Same as Default | Avoids newer visual effects, so it looks consistent across browsers | Same as Compat |

- **Default** is our design, with frosted surfaces and a modern look. Choose it when you want the player to look like Video.js.
- **Neutral** has the same controls in a lighter design, closer to a classic control bar. Choose it to apply your brand to a finished design: set your accent color, font, and corner radius through <DocsLink slug="guides/customize-skins" anchor="set-the-skins-styles">CSS custom properties</DocsLink>.
- **Compat** has plain, unbranded surfaces. Choose it when the player should blend into content pages, such as an encyclopedia article. It avoids backdrop blur, anchor-positioned menu highlights, and squircle corners, which some browsers render differently or skip.
- **Scaffold** has Compat's controls with minimal styling: square corners, no shadows or blur, your page's font, and no transitions. Choose it as the foundation for your own design, when you plan to restyle the whole player rather than brand a finished one.

All four skins support the same <DocsLink slug="guides/browser-support">browsers</DocsLink>, keyboard shortcuts, and gestures. To build your own design instead, add Scaffold's [source](#skin-source-in-your-project) to your project, start from another skin's source, or build a [custom interface](#custom-interface).

## Packaged skins and skin source

When you choose a skin, you can import the packaged version or add its source to your project. It's usually easiest to start with a packaged skin and add its source when you need more customization.

Packaged skins cover common visual changes through documented CSS custom properties. Packaged video skins also let you replace the poster. When you need more than that, add the skin source to your project and change the components and styles directly.

| Packaged skin | Skin source in your project |
|---------------|-----------------------------|
| Single component | Many UI components |
| Documented CSS custom properties | Editable components and styles |
| Future design updates auto-applied by bumping the version | Future design updates manually applied, or intentionally ignored |

### Packaged skin

<FrameworkCase frameworks={["html"]}>

```html
<script type="module">
  import '@videojs/html/video/player';
  import '@videojs/html/video/skin';
</script>

<video-player>
  <video-skin>
    <video src="video.mp4"></video>
  </video-skin>
</video-player>
```

</FrameworkCase>
<FrameworkCase frameworks={["react"]}>
```tsx title="Player.tsx"
import { Video, VideoPlayer, VideoSkin } from '@videojs/react/video';
import '@videojs/react/video/skin.css';

export function Player() {
  return (
    <VideoPlayer>
      <VideoSkin>
        <Video src="video.mp4" />
      </VideoSkin>
    </VideoPlayer>
  );
}
```
</FrameworkCase>

Don't depend on elements, class names, or undocumented custom properties inside a packaged skin. They may change between releases.

## Skins, features, and presets

Each skin is built with specific <DocsLink slug="guides/features">features</DocsLink> in mind. For example, a video skin renders fullscreen and picture-in-picture controls. An audio skin doesn't.

</FrameworkCase>
