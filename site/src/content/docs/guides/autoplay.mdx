For the best chance of autoplay succeeding, start playback muted and enable inline playback. Autoplay is a request, not a guarantee: browsers can block it based on audio state, prior interaction with your site, browser settings, and platform policy.

## Recommended approach

Set autoplay, muted, and inline playback on the media element, and keep a manual play control available for when autoplay is blocked.

## How it works

<FrameworkCase frameworks={["react"]}>

The `autoPlay`, `muted`, and `playsInline` props on <DocsLink slug="reference/components/video">`Video`</DocsLink> and similar media components pass through to the underlying media element. The media element applies the props it supports and requests playback as soon as it has enough data.

</FrameworkCase>
<FrameworkCase frameworks={["html"]}>

The `autoplay`, `muted`, and `playsinline` attributes on `<video>` and similar media components pass through to the underlying media element. The media element applies the attributes it supports and requests playback as soon as it has enough data.

</FrameworkCase>

The <DocsLink slug="reference/api/feature-playback">playback feature</DocsLink> reflects the result in player state. When autoplay succeeds, `paused` becomes `false` and `started` becomes `true`. When the browser blocks autoplay, the player stays `paused: true` with `started: false`, and the <DocsLink slug="reference/components/play-button">Play button</DocsLink> renders its play state. There is no separate autoplay failure event: a blocked autoplay looks like media that never started.

Calling `play()` from player state returns the native promise from the media element. When the browser blocks playback, that promise rejects with a `NotAllowedError`.

## Availability and constraints

<FrameworkCase frameworks={["react"]}>
- Autoplay can fail. Browsers decide per page load based on audio state, whether the user has interacted with your site before, browser settings, and platform policy.
- Muted autoplay is broadly allowed. Unmuted autoplay is blocked on first visit in most browsers; do not rely on it.
- Without inline playback, iPhone Safari opens the video in fullscreen when playback starts.
- Low-power mode and data-saver settings can block even muted autoplay. This is why the recommended approach keeps a manual play control.
- Programmatic volume control is unsupported on some platforms. The <DocsLink slug="reference/api/feature-volume">volume feature</DocsLink> reports support through `volumeAvailability`. It starts as `'unavailable'` before media attachment. On iOS Safari, it reports `'unsupported'`.
- This guide applies to media components that render a video element (Video, HlsJsVideo, DashVideo, MuxVideo, and the like). Embed components (YouTube, Vimeo, TikTok, Twitch) forward autoplay to the third-party player, which applies its own autoplay rules; muted and inline behavior varies by provider.
</FrameworkCase>

## Common variations

### Background video

<FrameworkCase frameworks={["react"]}>

Use `BackgroundVideo` for an MP4 or WebM file, `HlsBackgroundVideo` for an HLS stream, or `MuxBackgroundVideo` for a complete Mux HLS URL.

</FrameworkCase>
<FrameworkCase frameworks={["html"]}>

Use `<background-video>` for an MP4 or WebM file, `<hls-background-video>` for an HLS stream, or `<mux-background-video>` for a complete Mux HLS URL.

</FrameworkCase>

These components default to muted, looping playback without player controls. Provide a separate motion control and respect reduced-motion preferences. For setup and motion controls, follow <DocsLink slug="guides/background-video">Add a background video</DocsLink>. That guide also covers streaming backgrounds, which always autoplay and need conditional mounting.

### Autoplay with sound

Do not rely on unmuted autoplay for a user's first visit. Start playback from an explicit user action instead.

<FrameworkCase frameworks={["react"]}>

Call `play()` from the player store returned by <DocsLink slug="reference/api/use-player">`usePlayer`</DocsLink>:

```tsx
import { Container } from '@videojs/react';
import { usePlayer, Video, VideoPlayer } from '@videojs/react/video';

function StartPlaybackButton() {
  const store = usePlayer();

  return (
    <button type="button" onClick={() => store.play().catch(console.error)}>
      Play video
    </button>
  );
}

export default function App() {
  return (
    <VideoPlayer>
      <Container>
        <Video src="https://stream.mux.com/BV3YZtogl89mg9VcNBhhnHm02Y34zI1nlMuMQfAbl3dM/highest.mp4" playsInline />
        <StartPlaybackButton />
      </Container>
    </VideoPlayer>
  );
}
```

</FrameworkCase>
<FrameworkCase frameworks={["html"]}>

Call `play()` on the media element from a click handler:

```html
<video-player>
  <media-container>
    <video src="https://stream.mux.com/BV3YZtogl89mg9VcNBhhnHm02Y34zI1nlMuMQfAbl3dM/highest.mp4" playsinline></video>
  </media-container>
</video-player>
<button type="button" id="start">Play video</button>
<script type="module">
  import '@videojs/html/video/player';
  import '@videojs/html/ui/container';

  document.querySelector('#start').addEventListener('click', () => {
    document.querySelector('video').play().catch(console.error);
  });
</script>
```

</FrameworkCase>

Calling `play()` directly from the click handler lets the browser authorize unmuted playback. The promise can still reject; these examples log the rejection and leave the button available to retry. For source and decoding failures, see <DocsLink slug="guides/playback-errors">Handle playback errors</DocsLink>.

## Troubleshooting

### Playback does not start

Confirm that:

- The media is muted.
- Inline playback is enabled.
- The source loads (check the network panel).
- A manual play control is available as a fallback.

If autoplay is blocked, the player stays paused and the Play button remains in its play state; there is no error state to handle.

### The video opens fullscreen on iPhone

<FrameworkCase frameworks={["react"]}>

Enable inline playback with the `playsInline` prop on the media component.

</FrameworkCase>
<FrameworkCase frameworks={["html"]}>

Enable inline playback with the `playsinline` attribute on the media element.

</FrameworkCase>

### The video starts without sound

Expected with muted autoplay. Give the user a <DocsLink slug="reference/components/mute-button">Mute button</DocsLink> to unmute through an explicit action. Unmuting without a user action can cause the browser to pause or block playback. A <DocsLink slug="reference/components/volume-slider">Volume slider</DocsLink> can also unmute where volume control is supported; it hides on platforms such as iOS Safari.
