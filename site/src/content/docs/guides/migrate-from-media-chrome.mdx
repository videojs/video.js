## Before you begin

Check [Known gaps](#known-gaps) for controller options and preferences your app relies on. List your media sources, custom controls, event handlers, and theme rules.

Install Video.js and choose a <DocsLink slug="guides/presets">preset</DocsLink> (see <DocsLink slug="guides/installation">Installation</DocsLink>). If the preset's ready-made skin has the controls you need, start with it. To keep a custom control bar, build it from the individual Video.js UI components instead.

<FrameworkCase frameworks={["html"]}>
Before loading Video.js HTML, remove every Media Chrome import and CDN script from the page, including any that another component loads. Then reload the page. Both libraries register custom elements with names such as `media-play-button`. A document can hold only one definition per name, and Video.js keeps any definition that already exists. If you need both libraries during migration, load them in separate documents, such as an iframe.

For a page without a bundler, load the CDN video preset. It registers the player, the UI elements and icons used in the controller example below, and the `<media-i18n>` element:

```html
<script type="module" src="{{VJS10_CDN_BASE}}/video.js"></script>
```

Some elements in the mapping table below need separate bundles. If you use any of these elements, also load its bundle:

- `media-seek-button`: `{{VJS10_CDN_BASE}}/ui/seek-button.js`
- `media-playback-rate-button`: `{{VJS10_CDN_BASE}}/ui/playback-rate-button.js`
- `media-thumbnail`: `{{VJS10_CDN_BASE}}/ui/thumbnail.js`

Load each with `<script type="module" src="…"></script>`. See <DocsLink slug="guides/cdn">CDN</DocsLink> for individual component bundles.

For a bundler installation:

```bash
npm install @videojs/html
```
</FrameworkCase>

<FrameworkCase frameworks={["react"]}>
```bash
npm install @videojs/react
```

## Map the controller

The examples use the same MP4 source before and after migration. For HLS, DASH, or an embed, keep your existing source and choose its <DocsLink slug="guides/media-sources">media component</DocsLink>.

<FrameworkCase frameworks={["react"]}>

Media Chrome's React package wraps its custom elements. `@videojs/react` ships native components instead. `VideoPlayer` comes from the video <DocsLink slug="guides/presets">preset</DocsLink>, and `Container` holds the media and controls:

```tsx
'use client';

import { Container, Controls, PlayButton } from '@videojs/react';
import { Video, VideoPlayer } from '@videojs/react/video';
import './player.css';

export function MyPlayer() {
  return (
    <VideoPlayer>
      <Container className="app-player-container">
        <Video className="app-player-media" src="video.mp4" playsInline />
        <Controls.Root>
          <Controls.Content className="app-player-controls">
            <PlayButton
              render={(props, state) => (
                <button {...props} className="player-play-button">
                  {state.paused ? 'Play' : 'Pause'}
                </button>
              )}
            />
          </Controls.Content>
        </Controls.Root>
      </Container>
    </VideoPlayer>
  );
}
```

Create `player.css` with the rules below for layout, button styling, and control visibility. If your framework does not allow global CSS imports in components, import `player.css` from the entry point your app uses for global styles. Alternatively, add these rules to your app's global stylesheet and remove the `./player.css` import:

```css title="player.css"
.app-player-container {
  position: relative;
  width: 100%;
  aspect-ratio: 16 / 9;
}

.app-player-media {
  display: block;
  width: 100%;
  height: 100%;
  object-fit: contain;
}

.app-player-controls {
  position: absolute;
  inset-inline: 0;
  bottom: 0;
  display: flex;
  padding: 0.75rem;
  background: rgb(0 0 0 / 70%);
}

.app-player-controls:not([data-visible]) {
  visibility: hidden;
  pointer-events: none;
}

.player-play-button {
  padding: 0.5rem;
  color: white;
  cursor: pointer;
  background: #222;
  border: 1px solid white;
  border-radius: 0.25rem;
}

.player-play-button:focus-visible {
  outline: 2px solid white;
  outline-offset: 2px;
}
```

A preset player has a fixed set of <DocsLink slug="guides/features">features</DocsLink>. For a custom set, call <DocsLink slug="reference/api/create-player">`createPlayer`</DocsLink> once outside your React component. Pass it the feature list, then use the `Player` component and typed `usePlayer` hook it returns.

```tsx
import { createPlayer } from '@videojs/react';
import { videoFeatures } from '@videojs/react/video';

const { Player } = createPlayer({ features: videoFeatures });
```

Read player state with <DocsLink slug="reference/api/use-player">`usePlayer`</DocsLink>, `useMedia`, and <DocsLink slug="reference/api/use-store">`useStore`</DocsLink>. Player hooks must run in a descendant component rendered inside `VideoPlayer` or the `Player` returned by `createPlayer`. A hook called in the component that renders `VideoPlayer` or `Player` is outside that provider. Call the hook from a child component.

## Map controller attributes

<FrameworkCase frameworks={["react"]}>
Media Chrome configures behavior through `<media-controller>` attributes. Video.js v10 has no single controller component, so these settings move to three places:

- **Player features** — playback behavior that comes from the player's feature set. A preset includes a fixed feature set. With `createPlayer`, you choose the feature set.
- **`Container` and `Controls`** — layout, focus, and autohide.
- **Dedicated components** — `Hotkey`, `Gesture`, and similar components, rendered inside the player.

| Media Chrome attribute | Video.js v10 | How |
|---|---|---|
| `audio` | the audio preset | Choose an audio player and audio skin rather than toggling at runtime. |
| `autohide` | `Controls` (built in) | Controls hide after inactivity by default. For `autohide="-1"`, set `visibility="always"` on `Controls.Root`. The delay is not configurable yet; see [Known gaps](#known-gaps). |
| `fullscreenelement` | `Container` | Fullscreen targets the container element. |
| `gesturesdisabled` | `disabled` on each `Gesture`, or omit it | Media Chrome disables all gestures at once. In Video.js, set `disabled` on each `Gesture` or omit it. |
| `nohotkeys` | `disabled` on each `Hotkey`, or omit it | Media Chrome disables all hotkeys at once. In Video.js, set `disabled` on each `Hotkey` or omit it. |
| `hotkeys="noarrowleft …"` | individual `Hotkey` | Each shortcut is its own component, so remove the ones you don't want. |
| `keyboardforwardseekoffset`, `keyboardbackwardseekoffset` | `value` on `Hotkey` | Set the signed seek amount per component. |
| `defaultsubtitles` | `<track default>` for authored tracks | Add `default` to an authored captions or subtitles track. For tracks supplied by a provider or manifest, Video.js has no player-level setting that picks the default. |
| `defaultstreamtype` | `streamType` feature | Partial support. Video.js reads the stream type from the media. You cannot set a default stream type for use before the media loads. |
| `liveedgeoffset`, `seektoliveoffset` | live media engine | Live-edge behavior lives in the playback engine, not a UI attribute. |
| `lang` | `I18nProvider` | Wrap the player in `I18nProvider` and pass `locale`. See <DocsLink slug="guides/internationalization">Internationalize the player</DocsLink>. |
</FrameworkCase>

### Hotkeys

<FrameworkCase frameworks={["react"]}>
Media Chrome toggles keyboard shortcuts with `nohotkeys` and `hotkeys`. Video.js declares each shortcut as its own component, so you opt in to exactly the keys you want and set seek offsets inline:

```tsx
import { Hotkey } from '@videojs/react';

<>
  <Hotkey keys="Space" action="togglePaused" />
  <Hotkey keys="m" action="toggleMuted" />
  <Hotkey keys="ArrowRight" action="seekStep" value={5} />
  <Hotkey keys="ArrowLeft" action="seekStep" value={-5} />
</>
```

In a custom layout, render these components inside the player's `Container`. With installed skin source, edit its existing hotkey declarations.

To drop a shortcut, remove its component or pass `disabled`. There's no global "all hotkeys off" switch; omit the components you don't need.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
Media Chrome toggles keyboard shortcuts with `nohotkeys` and `hotkeys`. Video.js declares each shortcut as its own element, so you opt in to exactly the keys you want and set seek offsets inline:

```html
<media-hotkey keys="Space" action="togglePaused"></media-hotkey>
<media-hotkey keys="m" action="toggleMuted"></media-hotkey>
<media-hotkey keys="ArrowRight" action="seekStep" value="5"></media-hotkey>
<media-hotkey keys="ArrowLeft" action="seekStep" value="-5"></media-hotkey>
```

In a custom layout, put these elements inside the player's `<media-container>`. With installed skin source, edit its existing hotkey declarations.

To drop a shortcut, remove its element or add `disabled`. There's no global "all hotkeys off" switch; omit the elements you don't need.
</FrameworkCase>

### Gestures

<FrameworkCase frameworks={["react"]}>
Declare each tap or double-tap behavior with a `Gesture` component. For example, declare a tap that toggles playback, or a double-tap that seeks or enters fullscreen:

```tsx
import { Gesture } from '@videojs/react';

<>
  <Gesture type="tap" action="togglePaused" pointer="mouse" region="center" />
  <Gesture type="doubletap" action="seekStep" value={-10} region="left" />
  <Gesture type="doubletap" action="seekStep" value={10} region="right" />
</>
```

In a custom layout, render these components inside the player's `Container`. With installed skin source, edit its existing gesture declarations. A packaged skin already declares its own gestures, so do not add duplicates.

Remove a component or pass `disabled` to turn a gesture off.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>

## Map the elements

<FrameworkCase frameworks={["react"]}>
Most names carry over as PascalCase components without the `media-` prefix. Start with these name changes:

| `media-control-bar` | `Controls.Root`, `Controls.Group` | grouping |
| `media-time-range` | `TimeSlider` | "range" becomes "slider" |
| `media-volume-range` | `VolumeSlider` | "range" becomes "slider" |

| `media-playback-rate-menu` | `PlaybackRateRadioGroup` | inside `Menu` |
| `media-audio-track-menu` | `AudioTrackRadioGroup` | inside `Menu` |

## Rewrite your styles

Media Chrome reflects state in attributes such as `mediapaused`. Video.js uses `data-*` attributes such as `data-paused`.

```css
/* Media Chrome */
media-play-button[mediapaused] .play-icon { display: inline; }
```

<FrameworkCase frameworks={["html"]}>
```css
/* Video.js HTML */
media-play-button[data-paused] .play-icon { display: inline; }
```
</FrameworkCase>

<FrameworkCase frameworks={["react"]}>
```css
/* Video.js React: target the className on your rendered button */
.player-play-button[data-paused] { /* your paused-button styles */ }
```
</FrameworkCase>

Values that change continuously, such as slider position, use CSS custom properties: sliders expose `--media-slider-fill` and `--media-slider-pointer`.

### Map theme variables by meaning

Media Chrome and Video.js both use names beginning with `--media-`, but the shared prefix does not make their variables compatible. Keep a variable only when its documented meaning matches.

| Media Chrome theme variable                         | Packaged Video.js skin | Migration                                                                                           |
| --------------------------------------------------- | ---------------------- | --------------------------------------------------------------------------------------------------- |
| `--media-accent-color` or `--media-range-bar-color` | `--media-accent-color` | Closest match for slider fills and accented controls.                                               |
| `--media-primary-color`                             | no direct equivalent   | Often colors every control icon in Media Chrome; Video.js's accent variable colors fewer parts of the skin. |
| `--media-secondary-color`                           | no direct equivalent   | Add the skin source and write CSS for this color.                                       |
| `--media-control-background`                        | no direct equivalent   | Add the skin source and author the CSS.                                                             |
| `--media-control-hover-background`                  | no direct equivalent   | Add the skin source and author the CSS.                                                             |
| `--media-range-track-height`                        | no direct equivalent   | Add the skin source and author the slider CSS.                                                      |

The packaged Video.js skins expose eight custom properties:

- Colors: `--media-accent-color`, `--media-accent-text-color`, and `--media-border-color`.
- Corners: `--media-border-radius`.
- Interface font: `--media-font-family`.
- Media and poster fit and position: `--media-object-fit` and `--media-object-position`.
- Control sizing: `--media-scale-unit`.

See <DocsLink slug="guides/customize-skins" anchor="style-a-packaged-skin">Customize skins</DocsLink> for their meanings and defaults. Do not assume another Media Chrome variable will work because its name starts with `--media-`.

## Themes become skins

Media Chrome's `<template>`-based themes (`media-theme`) become Video.js <DocsLink slug="guides/skins">skins</DocsLink> and <DocsLink slug="guides/presets">presets</DocsLink>. Start from a preset, then <DocsLink slug="guides/customize-skins" anchor="style-skin-source">add its skin source to your project</DocsLink>.

<FrameworkCase frameworks={["html"]}>
Ready-made HTML skins keep their controls inside Shadow DOM. Code outside the skin sees a click as coming from the skin, not the button inside it. Some control events also stay inside the skin. Do not use an outside listener to identify which built-in button was clicked.

Keep playback event handlers on your `<video>` or `<audio>`. When you build a custom control bar, attach click and input handlers directly to those controls. With a ready-made skin, read media or player state instead of listening for clicks inside the skin.

Keep the skin when its CSS variables and content slots cover your changes. Build a custom control bar when you want to start from scratch. Add the skin source to your project when you want its existing layout and styles but need to change the controls inside it.
</FrameworkCase>

<FrameworkCase frameworks={["react"]}>
React skins do not use Shadow DOM. Use `render` props when you build individual controls. Add a ready-made skin's source to your project when you need to change its controls or layout.
</FrameworkCase>

## Control the player imperatively

Use <DocsLink slug="reference/api/player-store">store actions</DocsLink> such as `play`, `pause`, `seek`, `setVolume`, `requestFullscreen`, and `exitFullscreen` to control playback and UI state.

<FrameworkCase frameworks={["html"]}>
Call actions on the player element's store only after `player.store.target` is set, which means the media has attached. Fullscreen requests must run from a user interaction:

```html
<button id="toggle-fullscreen" type="button">Toggle fullscreen</button>

<script type="module">
  await customElements.whenDefined('video-player');
  const player = document.querySelector('video-player');

  document.querySelector('#toggle-fullscreen').addEventListener('click', () => {
    if (!player.store.target) return;

    if (player.store.isFullscreen) {
      player.store.exitFullscreen();
    } else {
      player.store.requestFullscreen();
    }
  });
</script>
```
</FrameworkCase>

<FrameworkCase frameworks={["react"]}>
Select an action with the same <DocsLink slug="reference/api/use-player">`usePlayer`</DocsLink> hook you read state with:

```tsx
import { usePlayer } from '@videojs/react/video';

function FullscreenShortcut() {
  const isFullscreen = usePlayer((state) => state.isFullscreen);
  const requestFullscreen = usePlayer((state) => state.requestFullscreen);
  const exitFullscreen = usePlayer((state) => state.exitFullscreen);

  return (
    <button type="button" onClick={() => isFullscreen ? exitFullscreen() : requestFullscreen()}>
      Toggle fullscreen
    </button>
  );
}
```
</FrameworkCase>

Keep native media calls such as `video.play()` and assignments such as `video.currentTime = 30`. Video.js updates player state from media events. Set `src` on the media component to change content, and replace the component when the source needs a different playback engine.

<FrameworkCase frameworks={["react"]}>
For video-backed media, a `ref` points to the rendered `HTMLVideoElement`. YouTube and Vimeo refs point to an `HTMLIFrameElement`. To call media methods on those embeds, pass a `mediaRef`, which receives the playback adapter, or call `useMedia()` from a component inside the player.

`useMedia()` returns the Video.js media object. If that object exposes an `engine` property, use it to access the playback engine.
</FrameworkCase>

## Known gaps

These Media Chrome features have no direct equivalent yet. Several can be approximated; see [Workarounds](#workarounds).

- No configurable `autohide` delay and no `autohideovercontrols` ([#1728](https://github.com/videojs/v10/issues/1728)). To disable autohide (`autohide="-1"`), set `visibility="always"` on the controls component; see [Workarounds](#workarounds).
- No `defaultduration` placeholder before the media loads ([#1729](https://github.com/videojs/v10/issues/1729))
- Volume and muted preferences are not persisted across sessions, so Media Chrome's `novolumepref` and `nomutedpref` opt-outs have nothing to opt out of ([#944](https://github.com/videojs/v10/issues/944)). Video.js can choose an initial subtitle track from the locale, but it does not yet remember the viewer's later language choice ([#1786](https://github.com/videojs/v10/issues/1786)).
- No `breakpoints` or container-breakpoint attributes; use CSS container queries instead
- No `seektoliveoffset` or `noautoseektolive` controls, and live-edge offset and tolerance aren't configurable ([#1730](https://github.com/videojs/v10/issues/1730))
- Chapters render and each time-slider segment reflects `data-active`, but there's no player-level active chapter value, `chapterchange` event, or menu for jumping between chapters ([#1873](https://github.com/videojs/v10/issues/1873))
- Cue points are not supported ([#1442](https://github.com/videojs/v10/issues/1442))

<FrameworkCase frameworks={["react"]}>
Chapters still work. Add a `<track kind="chapters">` with the `default` attribute. The packaged skins then split the time slider into chapter segments and show the chapter title on hover, via `TimeSlider.Chapters` and `TimeSlider.ChapterTitle`.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
Chapters still work. Add a `<track kind="chapters">` with the `default` attribute. The packaged skins then split the time slider into chapter segments and show the chapter title on hover, via `media-time-slider-chapters` and `media-time-slider-chapter-title`.
</FrameworkCase>

## Workarounds

### Disable autohide (`autohide="-1"`)

<FrameworkCase frameworks={["react"]}>
Set `visibility="always"` on `Controls.Root` to keep the controls visible regardless of activity. Packaged skins do not expose this prop. To keep a packaged skin's look, <DocsLink slug="guides/customize-skins" anchor="style-skin-source">add its source to your project</DocsLink> and set `visibility="always"` on its controls component.
</FrameworkCase>

<FrameworkCase frameworks={["html"]}>
Set `visibility="always"` on `media-controls` to keep the controls visible regardless of activity. Packaged skins do not expose this attribute. To keep a packaged skin's look, <DocsLink slug="guides/customize-skins" anchor="style-skin-source">add its source to your project</DocsLink> and set `visibility="always"` on its controls element.
</FrameworkCase>

### Breakpoints

For custom UI, add a class to your container and another to the controls you want to change. Define and query your own CSS container:

```css
.app-player-container {
  container-type: inline-size;
  container-name: app-player;
}

@container app-player (width > 40rem) {
  .app-player-controls { /* your wide layout */ }
}
```

Packaged HTML skin controls are inside Shadow DOM; external selectors cannot reach them. React skin selectors are private. To change a packaged skin's responsive layout, <DocsLink slug="guides/customize-skins" anchor="style-skin-source">add its source to your project</DocsLink> and edit the container queries in its local styles.

### Default duration

There is no player input for a duration placeholder. Set `preload="metadata"` to request the duration before playback. The duration is available only after the network request and engine loading finish. If you defer loading, render a static placeholder in your own UI.

### Preference persistence

Media Chrome remembers volume, muted state, and language across sessions. Video.js does not persist these preferences. Follow <DocsLink slug="guides/user-preferences">Remember user preferences</DocsLink> to restore and save them in your app.

Actions throw before the media attaches. Wait until `store.target` is set, restore the saved values, and then start saving changes. For captions or quality, also wait for the relevant track or rendition list before restoring a selection.

### Live edge offsets

`seektoliveoffset` and `noautoseektolive` are governed by the playback engine rather than the UI layer, so there's no attribute to tune them today. As a workaround, build a custom live control that reads player state through `selectLive` and `selectTime`.
