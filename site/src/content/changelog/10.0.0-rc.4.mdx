This release makes the docs and setup path more reliable, and gives stalled HLS playback a way back to automatic quality selection.

## Docs and installation

When `@videojs/cli agents init` finds an `index.html` without a `package.json`, it now chooses CDN installation by default. That keeps static, hand-written, and WordPress-style sites from gaining an unnecessary bundler; explicit `--method packaged` choices still work as before ([#2983](https://github.com/videojs/v10/pull/2983)). See the [CDN installation guide](/docs/guides/installation/cdn) for the browser-ready setup.

Docs pages reached through client-side navigation can play their preview media again, and the sidebar now switches between Guides, Components, and API in place, including keyboard navigation and a mobile menu that stays open ([#2986](https://github.com/videojs/v10/pull/2986), [#2987](https://github.com/videojs/v10/pull/2987)). We also corrected package README license links, the Video.js 8 migration example, and the [media sources guide](/docs/guides/media-sources) so it accurately describes the `source` support in `HlsVideo` and `HlsAudio` ([#2985](https://github.com/videojs/v10/pull/2985)).

## HLS quality recovery

Choosing Auto from the quality menu now takes effect while an hls.js stream is stalled, so playback can abandon a slow manual rendition and select a lower one. Manual quality choices also apply when they match the next buffered rendition ([#2979](https://github.com/videojs/v10/pull/2979)). See [Add a quality selector](/docs/guides/quality) for the player-side controls.
